# Experimental protocol (frozen)

Frozen on 2026-10-24, before any of the new evaluations listed here were run.
Baseline of the original study: git tag `baseline-artifact-v7` (commit 8960e04).
All historical test sets had already been observed in the original study; they are reused as-is and this is declared in the paper.

## Research question

Under which conditions do zero-shot decision models outperform compact classifiers adapted to the task,
and how does the comparison change with the label budget, the category descriptions and a shift in the test distribution?

## Data

| Task | Language | Classes | Train pool | Test (historical, frozen) | Notes |
|---|---|---:|---:|---:|---|
| banking77 | en | 77 | 9,993 | 1,000 | stratified subsample of the official test (seed 42) |
| massive_it | it | 60 | 11,514 | 996 | stratified subsample of the official it-IT test (seed 42) |
| ottavo | it | 24 | 1,669 | 960 | synthetic, written by Claude Sonnet subagents from the label specification |
| ottavo_adv ("lexical stress") | it | 24 | same train as ottavo | 601 | same task, lexically adversarial test; not an independent domain |

Example IDs are positional in the frozen files (`<task>-test-NNNN`, `<task>-train-NNNNN`). File hashes, few-shot subsets,
validation splits, API subsets and label permutations are in `data/manifests/<task>.json`, generated by `python -m dmstudy.make_splits`.

## Label budgets

Budgets are total task labels: k examples per class, k in {5, 10, 20, 50}, plus full. For each seed in {17, 42, 123}
the per-class examples are nested (5 ⊂ 10 ⊂ 20 ⊂ 50) and identical across methods. Classes with fewer than k training
examples contribute all they have (no duplication); shortfalls are listed in the manifest. Seeds vary jointly the subset
and the training randomness; the paper reports them as combined run-to-run variability.

## Hyperparameter selection (no test data)

- k-shot regimes: recipe chosen by stratified 5-fold cross-validation inside the k-shot budget (or leave-one-out folds when k = 5
  is too small for a stratified split), then retrained on the whole budget. No external validation labels.
- full regime: recipe chosen on `full_val[seed]` (10% of the train pool), then retrained on the whole train pool for the chosen duration.
- Grid for LoRA/QLoRA (E02): learning rate in {5e-5, 2e-4} x epochs/steps in three durations; for each family the grid
  and the number of configurations tried are reported.
- The historical "original recipe" (epochs = clamp(ceil(4000/n), 3, 40), single seed 0) is re-run unchanged as a reference.

## Category descriptions (E03)

- N: label names (underscores replaced by spaces), identical to what the original study gave the APIs for the public datasets.
- D: label names plus a short description with inclusion rule and boundary with confusable classes.
  For banking77 and massive_it, D was written on 2026-10-24 by Claude Opus subagents that could read only the training
  file and the label list (`data/descriptions/*_D.json`); test data was not accessible to them.
  For ottavo, D is the one-line specification that was used to generate the data (`data/ottavo/labels.json`).
- Instruction text and option order are identical between N and D. Main comparison uses the canonical order (permutation 0);
  order sensitivity uses permutations 1-3 on the frozen stratified API subset.

## Systems

- Decision APIs: OpenAI Decisions (requested model `gpt-6-luna`), Base Labs Elephant-1 and Mammoth-1 via Baseten System One.
  Probabilities are the per-option distribution returned by the API, renormalised over the valid options; the API `confidence`
  field is stored but never used as a probability.
- Generalist zero-shot control: Qwen3-8B (and Qwen3.5-9B if feasible) scored by next-token probability over option letters,
  renormalised over the valid letters (a distribution conditional on the offered options).
- Supervised compact classifiers: TF-IDF + logistic regression, SetFit (encoder `intfloat/multilingual-e5-base`),
  mmBERT-base fine-tuning, Qwen3-0.6B/1.7B LoRA and Qwen3-8B QLoRA with a classification head.

## Metrics and statistics

- Primary: macro-F1 over the classes present in the test gold. Secondary: accuracy, per-class F1 with supports.
- Failed API calls stay in the denominator as errors; quality on answered cases and coverage are reported separately.
- Calibration: ECE with 15 equal-width bins on the maximum class probability, multiclass Brier score, reliability diagrams.
- Uncertainty: paired bootstrap over test examples (2,000 replicates, seed 20261024), resampling the empirical distribution,
  for the pre-declared primary contrasts in `reports/contrasts_primary.md`. Run-to-run variability (3 seeds) is reported separately.
- No claim of equivalence without a pre-declared margin.

## Budget and resources

OpenAI spend cap 10 USD for the new runs (tracked in `results/budget_openai.json`); few-shot-in-prompt and order permutations
run on the frozen API subset (300 examples, 288 for ottavo). Baseten endpoints were free of charge during the experiments
(promotional access until 2026-10-27); this is not a production price. Local GPU: RTX 4050 Laptop 6 GB; Colab Tesla T4 16 GB.

## Out of scope / blocked

Real customer messages with human gold labels (E06) and a real-data distillation study (E11) require data and annotators that
are not available; templates are provided and the paper states this limitation.

## Addendum 2026-10-24 (before any evaluation on it): robustness set Ottavo-R (E07)

`data/ottavo_r/test.jsonl`, 312 synthetic Italian messages for eight phenomena (negation, intent correction, multi-intent,
typo/colloquial pairs, lexical distractors, insufficient information, out-of-scope, very short colloquial). Written by two
Claude Sonnet sub-agents from the label specification only; labelled blind by two validators (Claude Opus, Claude Sonnet);
kept only when both validators confirmed the generator label (8 of 320 dropped; `data/ottavo_r/build_report.json`).
Each item has `split_role` dev/test (50/50 per phenomenon, typo pairs kept together): dev is used only to choose the
review threshold, test only for evaluation. Gold labels `ambiguous` and `out_of_scope` are outside the 24 classes; closed-set
systems are evaluated on them only through routing to human review (`python -m dmstudy.robustness`).
Systems trained on Ottavo are evaluated on Ottavo-R without retraining.
